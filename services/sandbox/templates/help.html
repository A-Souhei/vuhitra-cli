Help & Documentation

Comprehensive guide to Vuhitra CLI features and context management system

Overview

Vuhitra CLI is an intelligent context management system designed for Large Language Model (LLM) interactions. It organizes and manages different types of contextual information to enhance AI-assisted development workflows.

Key Features

Multi-Level Context

Organize information into Eternals, Pillars, Ephemerals, and Vanishers for optimal context management.

Mirror System

Create isolated workspaces for projects while keeping originals untouched.

MCP Integration

Extend functionality with Model Context Protocol servers and tools.

Coding Mode

Specialized mode with enhanced development tools and capabilities.

Context Types

Vuhitra CLI organizes context into four distinct types, each serving a specific purpose:

Eternals

Long-lasting, persistent context that remains relevant across sessions. Perfect for project documentation, coding standards, API references, and fundamental knowledge.

  • Use for: Documentation, guidelines, reference materials
  • Lifetime: Permanent until explicitly removed
  • Examples: Coding standards, API documentation, architecture guides

Pillars

Foundational context that forms the core understanding for specific domains or projects. These are the "pillars" that support your AI interactions.

  • Use for: Project-specific knowledge, domain expertise
  • Lifetime: Long-term, project-specific
  • Examples: Database schemas, system architecture, business logic

Ephemerals

Temporary, session-specific context that's relevant for current tasks. Automatically cleaned up to prevent context pollution.

  • Use for: Current task details, temporary notes, debug info
  • Lifetime: Session-based or time-limited
  • Examples: Current bug reports, feature requirements, meeting notes

Vanishers

Sensitive or deprecated information that should be hidden from context. Used to prevent LLMs from accessing outdated or sensitive data.

  • Use for: Deprecated code, sensitive info, archived materials
  • Lifetime: Marked for exclusion
  • Examples: Old implementations, secrets, archived features

Mirrors & Vanishers

The Mirror system creates isolated development environments where you can work on codebases without affecting the original files. Combined with Vanishers, this provides safe experimentation spaces.

How Mirrors Work

  1. Create a Mirror: Copy a project into a managed mirror directory
  2. Work Safely: Make changes, run experiments, test ideas
  3. Sync Changes: Selectively apply successful changes back to source
  4. Clean Up: Remove mirrors when done

Mirror + Vanisher Integration

Each mirror can have associated "vanisher" content - files or information that should be excluded from LLM context. This is useful for:

  • Excluding large binary files or dependencies
  • Hiding sensitive configuration or credentials
  • Removing deprecated code from AI suggestions

Bidirectional Sync

Mirrors support two-way synchronization:

  • Mirror → Source: Apply tested changes back to original
  • Source → Mirror: Pull latest updates from original

Model Context Protocol (MCP)

MCP servers extend Vuhitra CLI with additional tools and capabilities. They provide specialized functionality for different development tasks.

Available MCPs

Mirror+Vanisher Development MCP

Comprehensive development operations on mirrored directories. Includes 18 specialized tools:

  • Exploration: Structure analysis, tech stack detection, entrypoint discovery
  • Architecture: Pattern identification, dependency mapping
  • Code Management: Intelligent chunking for large codebases
  • Planning: Implementation plan generation
  • Quality: Testing, linting, formatting, type checking
  • Security: Secret scanning, vulnerability audits
  • Workflows: Feature implementation and bug fixing automation
Always ON in Coding Mode Cannot be manually toggled

Executor MCP

Code execution and file operations on mirrored directories. Includes 24 specialized tools:

  • Code Execution: Run Python, JavaScript, shell commands, and code snippets
  • File Operations: Create, update, append, delete, copy, and move files
  • Build & Compile: Run builds, compile code, create virtual environments
  • Package Management: Install Python (pip) and Node.js (npm) packages
  • Directory Operations: Create, delete, copy, move, and list directory structures
  • Docker Support: Build Docker images from Dockerfiles
Always ON in Coding Mode Cannot be manually toggled

MCP Management

Access the MCP Management page to:

  • View all registered MCPs and their tools
  • Enable/disable user-controllable MCPs
  • View detailed tool descriptions
  • Monitor MCP status and registration

Coding Mode

Coding Mode is a specialized operating mode that enables development-focused features and tools. When activated, it provides enhanced capabilities for software development tasks.

What Changes in Coding Mode?

Automatic MCP Activation

Two development MCPs are automatically enabled:

  • Mirror+Vanisher Development MCP - 18 planning tools for exploration, architecture, and quality
  • Executor MCP - 24 execution tools for running code, creating files, and building projects

Enhanced Features

Additional development-specific features and context are activated to support coding tasks.

Toggling Coding Mode

Coding mode is controlled via the CLI tool. When disabled (normal mode), development MCPs are automatically deactivated to maintain a cleaner context for non-coding tasks.

Mode Comparison

The table below shows which features are available in each mode:

2. Best Practices

  • Keep Eternals Focused: Only add truly persistent, broadly useful information
  • Clean Ephemerals Regularly: Remove outdated temporary context

  • Mark Sensitive Data as Vanishers: Prevent accidental exposure to LLMs
